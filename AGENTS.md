# Studio session instructions

This repository is the authorized independent Korean Arena 3D Studio. Keep the existing Vite app; do not access the production Korean Arena project. Each cloud task is isolated; use this checkout and do not create a worktree unless explicitly requested.

At the start of every session read STUDIO_TASKS.md, STUDIO_PROGRESS.md, STUDIO_DECISIONS.md and STUDIO_ASSETS.md; inspect Git status, recent commits and saved outputs. Continue the first unfinished task. Do not restart setup, reinstall working packages or regenerate approved assets without a concrete reason.

Follow STUDIO_MASTER_PROMPT.md. The user's latest prompt authorizes Studio implementation, original Blender models, animation, preview changes, exports and checkpoint commits/pushes. Keep source assets, provenance and validation evidence. Images are not meshes. Do not claim unmeasured FPS or an unverified milestone.

After each meaningful verified subtask, and before costly/lengthy operations, update the four progress files, preserve outputs, commit a checkpoint and push through the existing origin when available. Verify the remote SHA before claiming GitHub persistence. Never force push, delete uncommitted work or include secrets. If remote saving fails, record that progress is local. Use the required NEXT SESSION HANDOFF structure before ending work.

Use pinned package versions and npm lockfiles already present. Do not install optional agent skills, paid providers or external API services without explicit authorization. Keep original art cohesive; defer additional districts until the arena/mascot vertical slice has passed its visual and technical gates.

Current user review gate: the latest task is ONLY making the existing v0.2 showcase accessible and visually verified. Do not start Hangul Garden or any new district, regenerate models, change art direction or replace approved assets. After preview delivery, stop and wait for the user's visual feedback. Public Pages deployment requires the user's explicit approval; the prepared workflow is manual-only and must not be run just because a checkpoint was pushed. The onboarding UI exposes no user-facing localhost preview link. Deliver the tested HTTP ZIP/opening instructions or an approved, verified public URL.
