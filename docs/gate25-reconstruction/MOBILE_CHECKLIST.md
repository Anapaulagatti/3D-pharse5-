# Final mobile handoff — physical devices NOT TESTED

The original [full Android/iPhone procedure](../gate25/DEVICE_TESTING.md) is retained unchanged. This cloud session exposes no physical-device interface. Desktop Chromium touch emulation is not Android Chrome or iPhone Safari certification.

1. Extract the single reconstruction ZIP. Run `python3 start.py --lan` on a computer on the same trusted Wi-Fi. Open its printed path using the computer's LAN IP on the phone. No public deployment. Stop server with Ctrl-C.
2. Record actual device model, OS/browser versions, CSS viewport, screen/DPR, browser-bar/orientation and reduced-motion settings. Test one Android/Chrome and one iPhone/Safari.
3. In landscape, walk/run through **CURRENT · reconstruction / review pending** both ways; inspect both joins, complete beds/borders, crates and bollards, curbs and road paint, depth/occlusion, loading and no flicker. Jeju: Scenic drag/pinch, Overview and native Return, full coast→oreum→orchard→house tour. Check distinct first2 compositions, idle control collapse, obvious **Controls** restore, Pause/manual camera/Resume, Skip and Return. Ensure no accidental Juni movement. Repeat with reduced motion and landscape reversed.
4. **Export:** Return to Juni → Options(···) → Export test report. Save JSON before changing scenes (each scene/document resets its session). The JSON records client/viewport, raw update intervals, camera/player state, texture estimates and chunk request/ready events. Record physical model/OS yourself; the export explicitly does not certify physical-device identity. On iPhone use the browser's download/share sheet to save to Files.
5. Repeat camera modes20times and explore for at least15minutes; export at5and15minutes. Attach screenshots/actual screen recording, stutter/reload/control observations. Record measured memory/battery/thermal data only if available, with tool/conditions. Raw browser update cadence is not certified display FPS.
