# Movement correction

1. **Camera-side:** Follow mode used normalized raw input multiplied by 60px horizontally/42px vertically as an additional look-ahead target. Reduced motion set the interpolation coefficient to 1, making that entire displacement instantaneous at a key edge. A blocked key could also move the camera without moving the player. The hotfix removes input-dependent lead and follows the existing collision-resolved position. Scenic zoom/tour framing remains unchanged. Native pixel snapping and sampling remain in the existing renderer.
2. **Animation-direction selection:** Equal diagonal axes always selected vertical facing. Adding W to D therefore started a turn even though movement was still diagonally right. Near walls facing followed intended rather than traversed axes. The cardinal resolver retains the previous participating axis on ties and selects the actual traversed axis after the existing sweep. It does not add a delay or rewrite any atlas, stride, speed or animation clip.
3. **Cosmetic synchronization:** Cosmetics remain baked into the same native atlas/frame as the body; no separate screen-space sprite was added. Head-patch defects were in native art ownership/registration, not a separate camera-follow layer. Existing 96×112 registration/48,100 anchor remains unchanged.

There is no claim that all browser frame pacing or hardware stutter is solved. Host capture and emulated-device performance are separate from the reproducible input-lead regression. Original character transitions, pivots and authored pixels were preserved. Before/after videos and traces are real Phaser captures. CAMERA_REGRESSION.json records a dedicated reduced-motion reproduction; do not substitute a build or unit result for that proof.
