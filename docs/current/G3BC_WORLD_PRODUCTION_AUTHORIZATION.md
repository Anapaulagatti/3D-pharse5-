## 7. CHANGE THE DEFECT-HANDLING STRATEGY

Stop treating every minor defect as an immediate production blocker.

Create one centralized:

`GATE3_MASTER_DEFECT_REGISTER.md`

Classify defects:

**P0 — Critical / fix immediately**

- Data loss or source destruction.
- Broken build or world-loading architecture that prevents progress.
- Systemic coordinate errors that corrupt multiple districts.
- Irreversible changes to protected assets.
- Technical failures preventing independent production work.

**P1 — Major / must fix before final world acceptance**

- Important routes blocked.
- Unreachable required destinations.
- Serious collision and navigation problems.
- Major world-layout incompatibilities.
- Persistent rendering or memory failures.

**P2 — Visual / batch repair after assembly**

- Blurry local textures.
- Visible chunk seams.
- Sliced trees or awkward planters.
- Small lighting inconsistencies.
- Minor pavement or landscape discontinuities.
- Repetitive vegetation.

**P3 — Optional final polish**

- Small decorative details.
- Subtle environmental variation.
- Minor presentation and animation refinements.

P1–P3 issues must remain visible in the defect register with location, screenshot, severity, affected assets and proposed fix.

Do not repeatedly interrupt full-world production for P2/P3 issues.

Address P1 problems when they obstruct integration; otherwise schedule their resolution in G3-D.

Never mark a known defect PASS simply because production has moved to another phase.
